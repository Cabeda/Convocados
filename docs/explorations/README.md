# Exploration notes

One file per implementation wave, named after the branch or ticket set
(`2026-10-important-bugs-wave2.md`). Explorers and wave leads commit their
findings here — code locations, verified reproduction commands, decisions and
their reasons — so the next session's implementers and reviewers can read
them.

Notes live in the repo rather than `/tmp` because `/tmp` dies with the
machine, and sparse context pointers go stale. Keep them short; they are
context, not documentation. Nothing here replaces `AGENTS.md`,
`CODING_STANDARDS.md`, or the tickets themselves — they are the record of
what was learned *before* the code was written.
